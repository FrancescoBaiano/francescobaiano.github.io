// 02 — THE CHALLENGE

Reconstructing 3D models at runtime from files and MRI.

The core engineering challenge was making the application dynamically reconstruct 3D anatomical models at runtime directly from selected 3D files or raw MRI data. Instead of relying on pre-baked assets, the system had to generate accurate models on demand, ensuring seamless inspection for clinicians across desktop and VR.

01 / CORE PIPELINE

Runtime 3D Generation

Reconstructing anatomical 3D models on the fly from user-selected files or underlying MRI datasets.

02 / DUAL PLATFORM

Unified PC & VR Workflow

Adapting interaction mechanics to work smoothly with desktop peripherals and immersive VR controllers.

03 / PRECISION

Deep Organ Analysis

Isolating complex overlapping structures through custom materials, scaling, and per-organ transparency.

// 03 — REAL-TIME RECONSTRUCTION

The model is built while you use the app.

The anatomical models are not pre-made scene assets. When the user picks a model from inside the application, the 3D model is reconstructed at runtime from MRI data and shown immediately, ready to be inspected on PC or in VR.

STEP 01

Select a model

The user chooses the model to explore directly from the application interface.

STEP 02

Rebuild at runtime

The 3D model is reconstructed in real time from the MRI data of the selected model.

STEP 03

Inspect and adapt

Scale it, change its materials and adjust the transparency of each organ.

// 05 — TECHNICAL REFLECTION

What this project demonstrates.

This work is a practical example of real-time 3D development in Unity: generating a model at runtime from the user's selection, manipulating transforms, updating materials, and designing interactions that stay consistent across PC and VR. It strengthened my skills in Unity, runtime 3D and VR interaction design, and gave me first-hand insight into how immersive technologies are applied in healthcare.
